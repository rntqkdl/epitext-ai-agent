# EpiText-Agent: 구현 상태와 고도화 설계

기존 EpiText의 모델·화면을 활용해 판독 후보와 근거를 검토하는 워크플로우를 개발합니다. 현재 구현은 모의 도구 기반 프로토타입입니다. 이 문서에서 ‘구현할 것’은 이미 달성한 성과와 구분합니다.

## 1. 현재 확인된 범위

LangGraph 상태·노드·분기, 예시 문맥 보강, 로컬 JSON 검색, 후보 결합, 별도 API와 검토 화면이 있습니다. 새 도구 경로는 실제 모델을 호출하지 않습니다. 실제 판독 성능·업무 시간·비용 개선은 미측정입니다.

기존에 적힌 개선율, 실제 기관 간 이견 설명, 사례별 정답은 검증된 성과에서 제외합니다. 예시 데이터는 처리 흐름 점검에만 사용합니다. 기존 연구 성과를 이번 에이전트의 결과로 승계하지 않습니다.

## 2. 서비스 목적과 범위

주 사용자는 금석문 판독 연구자입니다. 한 글자나 손상 구간의 후보를 비교하고, 어떤 문맥과 사료가 각 후보에 관련되는지 검토하는 일을 지원합니다. 번역·아카이브 담당자는 결과를 활용하는 보조 사용자로 둡니다.

입력은 원본 이미지·대상 위치·OCR 결과·확인된 문맥·선택적 시대/문헌 메타데이터입니다. 출력은 후보 목록, 사용 문맥과 가정, 실제 인용 구절, 불일치·미확인 사항, 사람의 결정과 이력입니다. 목표는 검토 준비와 기록 업무의 지원이며, 유일한 역사적 정답의 자동 확정을 보장하지 않습니다.

## 3. 먼저 복구할 기반 기능

| 우선순위 | 작업 | 완료 기준 |
|---|---|---|
| P0 | 평가 자료·출처 정리 | 원문 URL·판본·문자 위치·허용 판독이 연결된 manifest |
| P0 | 실제 모델 도구 연결 | 실제 이미지·문맥에서 후보 반환, 모델/전처리 버전 저장 |
| P0 | 업로드·후보·검토 API 연결 | 실제 작업의 결과가 화면에 나타나고 선택 후보를 저장·재조회 |
| P0 | 저장·오류·빌드 수정 | 대상 ID 일치, DB 실패가 실패로 표시, 깨끗한 설치·빌드 성공 |

새 기능보다 이 경로를 먼저 완성합니다. 실제 도구와 판독 자료가 없으면 에이전트의 효과를 평가할 기준도 없습니다.

## 4. 핵심 고도화 A: 되돌릴 수 있는 문맥 가설

부분 훼손 후보를 앞뒤 문맥에 대입하는 방식은 잘못된 글자를 주변에 전파할 수 있습니다. 원본 OCR을 덮어쓰지 않고 가설을 별도로 둡니다.

- 원본: order·MASK type·bbox·원래 text를 보존합니다.
- 가설: 대입 문자·발생 도구·영향받는 위치·문맥 버전·이전 가설 ID를 기록합니다.
- 비교: 원래 문맥과 후보 A/B를 넣은 문맥의 결과를 구분합니다.
- 철회: 선행 가설이 바뀌면 그 가설에 의존한 결과만 무효화하고 재조사합니다.
- 종료: 같은 상태 반복, 새 근거 없음, 예산 소진이면 미상·복수 유지·사람 검토로 종료합니다.

성공 여부는 ‘한번 채웠다’가 아니라 잘못된 선행 가설을 넣은 사례에서 영향을 발견·철회하는지로 평가합니다. 처음에는 후보 분기를 두 개, 보완 조사를 한 차례로 제한하는 설정부터 시험합니다. 이 수는 실험 설정이며 최적값이 아닙니다.

## 5. 핵심 고도화 B: 후보별 사료 구절 비교

후보가 문헌에 등장한다는 사실과 대상 위치의 판독을 뒷받침한다는 사실을 구분합니다. 검색 결과를 바로 MLM 확률에 합산하지 않습니다.

각 결과에는 문헌·판본·원문 URL·구절 범위·인용문을 둡니다. 후보와의 관계는 지지·반대·관련만 있음·판단 불가로 표시합니다. 대상 시대와 문헌 편찬 시기를 별도로 보존하고, 불명 시대를 특정 왕조로 강제하지 않습니다.

검색은 같은 문구뿐 아니라 관직·인명·장르·관련 의례 등 조사 목적에 맞는 평행 구절을 찾는 방향으로 확장합니다. Aeneas 연구는 관련 비문의 문구·맥락상 평행 사례를 연구자의 조사 출발점으로 제공하는 접근을 제시합니다. 여기서는 그 검색·비교 관점을 참고하며, 라틴 비문 모델을 한국 금석문에 바로 적용하거나 성능을 승계한다는 뜻은 아닙니다. [Assael et al., Nature, 2025](https://www.nature.com/articles/s41586-025-09292-5)

첫 버전은 출처를 확인한 작은 코퍼스의 lexical 검색으로 시작합니다. dense 검색·리랭킹은 같은 질의셋에서 추가 효과가 확인될 때 도입합니다. 자동 판독본 정렬과 대규모 수집은 후속 범위입니다.

## 6. 핵심 고도화 C: 다음 조사를 선택하는 에이전트

분류·정렬·인용 위치 검사·예산 제한은 일반 코드로 처리합니다. 에이전트는 조사 계획과 근거 해석을 맡습니다. 다음 구성은 구현할 설계이며 현재 코드에 역할별 LLM이 연결된 것은 아닙니다.

| 역할 | 판단 | 도구·반환 |
|---|---|---|
| 복원 계획 역할 | 어떤 위치의 정보가 부족하고 무엇을 먼저 조사할지 | 대상·질문·다음 행동·예산 |
| 사료 조사 역할 | 어떤 자료를 검색하고 후보 A/B의 관련성을 어떻게 비교할지 | 실제 인용 ID·관련성·반대 근거·검색 한계 |
| 검증 역할 | 가설이 관찰·문맥·사료와 충돌하는지, 추가 조사가 필요한지 | 재추론·추가 검색·가설 철회·사람 검토·종료 제안 |

Swin·MLM은 위 역할이 사용하는 도구입니다. 서로 다른 이름의 모델 호출을 나열하는 것으로 멀티 에이전트를 설명하지 않습니다. 단일 에이전트와 역할 분리 구성도 같은 도구로 비교하고, 효과가 없는 역할은 일반 노드로 단순화합니다.

도구는 주입 가능한 인터페이스로 연결하고, 모의/실제 실행을 구분합니다. MCP를 사용한다면 실제 서버 등록·클라이언트 호출·결과 반환을 추적으로 확인합니다. 프롬프트에 쓴 가상 조사를 실제 검색으로 제시하지 않습니다.

## 7. 검토 화면과 결과 기록

한 검토 항목에 원본 크롭, 시각/문맥 후보, 원래/가설 문맥, 인용 구절, 미확인 사항, 사람의 결정을 묶어 보여줍니다. 번역은 미상·가설을 유지하는 초안으로 제공합니다.

사용자는 선택·수정·복수 유지·미상 중 결정합니다. 성공 표시는 실제 결정 ID와 저장 결과를 확인한 뒤 반영합니다. 대상 ID·분석 버전·근거 버전을 연결하고, 오래된 요청과 중복 요청을 구분합니다. 그래프 중단·재개를 추가할 때는 영속 체크포인터와 재시작 복원을 검증합니다.

자동 검토 제외 범위는 개발 자료에서 오판과 처리 범위를 함께 보고 조정합니다. 단순 softmax나 조화평균 점수에 고정 임계값을 두고 정답 확률로 해석하지 않습니다.

## 8. 공정한 비교와 한계

| 비교 조건 | 분리해 확인할 효과 |
|---|---|
| A: 기존 파이프라인 | 출발 기준 |
| B: 후보 보존·호출 최적화 | 일반 코드 개선 효과 |
| C: 문맥 가설·추가 조사 에이전트 | 조사 선택·재검증의 추가 효과 |

같은 자료·모델 revision·코퍼스 snapshot과 호출 예산을 사용합니다. 실제 훼손과 합성 손상을 분리하고, 평가 대상의 정답 판독본을 검색할 수 있는 조건도 따로 표시합니다. 검수 전후 결과와 미상·복수 판독 비율을 함께 보고합니다.

우선 지표는 후보 Top-k 포함률, 잘못된 가설의 전파·철회, 인용 구절 확인, 호출 수·실제 사용량·지연, 검토 준비 시간입니다. 현장 전문가 없이 측정한 시간을 전문가 생산성으로 일반화하지 않습니다.

추가 조사·LLM 호출은 비용과 지연을 늘릴 수 있습니다. 희귀 이체자·미상 시대·부족한 문헌은 해결되지 않을 수 있습니다. 이때 무엇을 모르는지와 어떤 자료가 더 필요한지를 결과로 남깁니다.

## 9. 구현 순서

1. 출처·평가 manifest와 실제 두 모델의 입력·출력 확인.
2. 저장·조회·빌드를 고치고 기존 입력에서 검토 재조회까지 연결.
3. 원본/가설 문맥과 영향 관계·철회 구현.
4. 실제 사료 구절 비교와 제한된 추가 조사 연결.
5. 역할별 에이전트·MCP·DI·추적의 필요 부분 적용.
6. A/B/C 비교 후 한계와 실제 시연 정리.

글리프 생성, 대규모 다면 문맥, 전면적인 화면 개편은 이 흐름을 완성한 뒤 검토합니다.
